## Acceptance criteria

The single `LiveDocument` mutation path now retains large fenced-code blocks and their rows for ordinary local edits. It incrementally updates the matching source-language parse, rebuilds only the changed line/style envelope, and rebases unchanged rows and later blocks. Contiguous projected `d`/`c` uses a rope range edit rather than a whole-document replacement; register and undo behavior is covered by differential tests. Delimiter and unsafe parse cases fall back to the complete builder before publishing a frame. The full builder and public API remain unchanged.

- [x] Routine local code-fence edits do not take the full 1 MiB model/layout or full-fence parse path; bounded-path counters and differential tests cover this.
- [x] One hundred verified cycles per Rust/Go delete/change case pass the <50 ms p99 public-pane target, including frame and undo checks.
- [x] Propagating language syntax, delimiter edits, and unprimed source trees take a faithful wider path; no partially styled rows are published.
- [x] Existing realistic, cold, ordinary edit, memory, core, standalone, and embedded checks remain green.
