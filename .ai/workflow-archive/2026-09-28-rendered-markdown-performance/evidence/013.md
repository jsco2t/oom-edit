Pane input and frame are timed separately; PTY receipt measures the combined event loop, host draw/write and terminal flush. The test-only mutation trace (`make bench-acceptance-1mb-mutation-phases`) shows a 15-line fence delete invokes the source parser 14–15 times and a **full** Markdown-model rebuild: 2,387 blocks and about 1,048,400 parsed bytes in each language. In the candidate, `LiveDocument::refresh_derived` loops over the 14–15 individual projected edits and calls `highlighter.apply_edit` and `model.apply_edit` for each; a large fence exceeds the retained model's 8 KiB local-block limit. In clean main the highlighter receives the edit batch once and there is no retained-model update in that input handler. This explains the candidate's much larger **input-handler** cost without attributing all of it to any one parser. The ignored diagnostic's debug-build wall-clock times are not compared to release performance.

The user reported kitty with held arrow keys. Standalone constructs `TerminalGuard::new()`, whose default has `keyboard_enhancement: false`; it does not enable kitty repeat-event reporting. The PTY sends legacy arrow sequences, which matches that startup path. A host may explicitly opt into enhanced keyboard events, whose Repeat events the adapter currently ignores; that is a separate existing behavior, not evidence for this standalone branch-only hitch. Kitty itself is not installed here, and PTY flush receipt cannot test its physical refresh. Thus the visual scroll hitch remains a real acceptance report, not a claim of user error; task 016 must retain an explicit terminal-presentation investigation/acceptance step rather than declaring the issue fixed from this profile.
