## Propagation and timing findings

At 1 MiB mixed Markdown, deleting an ordinary 163-byte line at either top or midpoint reports one Tree-sitter changed range spanning 1,048,378 bytes / 12,333 lines. The full model keeps 1,933 blocks and only one block changes row count. The top deletion changes 16,258 styled rows and the midpoint deletion changes 11,611, largely because one removed link renumbers later link markers; the candidate therefore indexes global link order and renders visible downstream rows with current marker numbers. The 144 KiB equivalents report 147,258 changed bytes / 2,613 lines but still only one block row-count change. Changed-range size is not semantic impact: a reference-definition edit reports only 40 bytes / two lines yet can affect document-wide links. A fence delimiter edit reports 3,305 bytes / 41 lines; a front-matter delimiter reports 34 bytes / four lines. Ordinary source-line Enter reports zero *structural* changed bytes despite a full parser invocation; heading edits report 68 bytes / two lines at top or 3,270 bytes / 38 lines near the midpoint. Fence-language changes also report zero structural changed bytes while current injection/reference discovery repeats on every key.

Adding candidate p99, direct Vim proxy p99 and even the entire existing warm public-pane frame p99 (about 6.4 ms source / 1.5 ms rendered, double-counting some frame work) yields roughly 16 ms source and 9 ms rendered. This is credible headroom under 50 ms, **not** a measured public-pane result; integration, exact global indices, and allocation effects remain to be tested.

## Main-thread review

The review strengthened repeated-cycle checks to compare all retained link destinations and changed-block rows, not merely their counts. The prototype's old/new-line guard catches creation/removal of definition and fence markers; global examples use the full oracle. The largest remaining risks are propagation beyond the edited block (definitions, footnotes, containers, marker renumbering), exact source highlighting after sequential edits, and the public full-layout API's eager `Vec` contract. Tasks 008–010 must prove their production solutions with randomized differential tests. Do not promote the test-only classifier or partial benchmark path directly into release code.
